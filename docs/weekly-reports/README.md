# Weekly Development Reports

Weekly reports are factual historical logs. They help the team and supervisor understand progress, verification, blockers, and planned work.

They are **not** requirements, architecture, design authority, or instructions for future implementation. Humans and AI tools must not steer product or technical decisions from these reports. Link to current GitHub issues, pull requests, requirements, and decision records instead.

## Naming

Use one file per project week:

```text
week-01-YYYY-MM-DD.md
week-02-YYYY-MM-DD.md
```

Use `TEMPLATE.md` and keep reports concise and evidence-based.

## Rules

- Report only completed work that is merged or clearly label it as in progress.
- Link issues and pull requests.
- Record exact tests and observed results.
- Record decisions only by linking an accepted decision record.
- Do not rewrite requirements inside the report.
- Do not include secrets, real guest data, or property access credentials.
- Correct factual mistakes openly rather than silently rewriting history.
